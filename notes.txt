	“How do Docker and Docker Compose work?”
A Docker image is an immutable template made of filesystem layers and metadata. 
Docker creates containers as running, isolated instances of those images using Linux namespaces and cgroups. 
Docker Compose reads the YAML file and creates the related containers, network, volumes, secrets and port mappings as one application.

	“Image with Compose versus without Compose?”
There is no special Compose image. The same image can be started manually with docker run or by Compose. 
Compose simply records and automates the runtime options that I would otherwise provide individually: 
network, volumes, secrets, restart policy, dependencies and ports.

	“Why Docker rather than virtual machines?”
Containers share the host kernel and isolate processes, networking and filesystems, so they start faster and require less memory and disk. 
A VM emulates virtual hardware and runs a complete guest kernel, which is heavier but provides stronger separation 
and can run a different operating system kernel.

	“Why this directory structure?”
Each service has its own Dockerfile, configuration and entrypoint, which keeps responsibilities and build contexts separate.
The Compose file describes how the services communicate, while the root Makefile provides one reproducible interface 
for building and managing the complete stack.



	on PID 1 and entrypoints
PID 1 controls the container lifecycle and receives Docker’s stop signals. 
The setup scripts finish with exec "$@", replacing the shell with MariaDB, PHP-FPM or NGINX.
The daemon therefore becomes PID 1, receives signals directly, and the container exits when the real service exits.

	on Docker network
A Docker bridge network is a private virtual network connecting the containers. 
Compose also provides internal DNS, so NGINX reaches PHP-FPM as wordpress:9000, and WordPress reaches MariaDB using the service name mariadb. 
Only explicitly published ports are reachable from the host.
